# Cluster cross-file findings

#### `CSCAN-cluster-consolidation-traversal-via-elixir-manifest`

- **Finding ID** — `CSCAN-cluster-consolidation-traversal-via-elixir-manifest`
- **Severity** — Medium
- **Confidence** — high
- **Files involved** —
  - `lib/mix/lib/mix/compilers/elixir.ex` — `read_manifest/1` :354-363 (plain `binary_to_term` at :356); `parse_manifest/2` :930-954 (the 11th field `old_protocols_and_impls`, :937-940); `stale_local_deps/5` :660-733 (:728-729); `protocols_and_impls_from_paths/1` :1427-1432 (:1429); `protocols_and_impls_from_modules/2` :1434-1443 (atoms taken verbatim, :1436-1440); consolidation tuple :214; `maybe_consolidate/4` → `Mix.Compilers.Protocol.compile/4` :1460
  - `lib/mix/lib/mix/compilers/protocol.ex` — `compile/4` :110-129 (:123 `diff_manifest`); `diff_manifest/3` :203-245 (:210, :233 `remove_consolidated`); `remove_consolidated/2` :247-250 (`File.rm(Path.join(output, "#{atom}.beam"))` :248); `consolidate_each/4` :165-190 (`File.write!` :171, `reload` :167→:198-201 `:code.purge`/`:code.delete`); `umbrella/2` :46
- **Finding shape** — "Safe because the caller checks" broken + Trust-boundary / validation split (untrusted atoms produced in file A, unconfined path sink in file B; neither file confines).
- **Evidence** —
  - **Sink (protocol.ex):** `remove_consolidated/2` builds a path from a protocol atom with no confinement — `File.rm(Path.join(output, "#{Atom.to_string(protocol)}.beam"))` (:248). It is reached from `diff_manifest/3` for every `old_protocols` atom absent from `new_protocols` (`for {protocol, _} <- old_protocols, not is_map_key(new_protocols, protocol), do: remove_consolidated(protocol, output)`, :230-233) and for version-bumped protocols (:209-210). `consolidate_each/4` likewise does `File.write!(Path.join(output, "#{Atom.to_string(protocol)}.beam"), ...)` (:171) and `reload(protocol)` → `:code.purge/:code.delete` (:198-201) on whatever atom arrives.
  - **Source (elixir.ex):** the protocol/impl atoms are produced by `protocols_and_impls_from_modules/2` (:1434-1443), which copies `module` and `protocol` atoms verbatim out of a manifest deserialized with plain, unhardened `:erlang.binary_to_term/1`. Those atoms reach protocol.ex through **two elixir.ex readers, not protocol.ex's own**: (a) `parse_manifest/2` decodes the main `compile.elixir` manifest and hands back its 11th field `old_protocols_and_impls` (:937-940), which `compile/7` packs into `consolidation` (:214) and `maybe_consolidate/4` passes as `old_protocols_and_impls` to `Mix.Compilers.Protocol.compile/4` (:1460) → `diff_manifest(new, old, output)` (:123) → `old_protocols`; (b) `stale_local_deps/5` (:728-729) and `protocols_and_impls_from_paths/1` (:1429) decode **local path-dependency** `compile.elixir` manifests and feed the `new_protocols`/`new_impls` side.
  - **Reachability:** in the ordinary (non-umbrella) `mix compile`, `after_compile` → `maybe_consolidate({:on, old, new}, …)` runs whenever any file was stale and consolidation status is `:on` (elixir.ex :199, :1176-1181, :1447-1468; status from protocol.ex `status/2` :87-108). So a `compile.elixir` manifest whose `old_protocols_and_impls` field is `{%{:"../../../../tmp/victim" => 1}, %{}}` triggers `File.rm("<consolidation>/../../../../tmp/victim.beam")` on a normal incremental compile — the confirmed out-of-tree delete primitive. (The `File.write!` side additionally requires a genuinely consolidatable protocol carrying such a name and is correspondingly unlikely; `reload/1`'s purge/delete fires for any atom that reaches `consolidate_each`.)
- **What the per-file pass missed** — The protocol.ex reviewer saw the traversal sink but attributed its untrusted atoms to protocol.ex's *own* `read_manifest` (`compile.protocols`) and proposed `[:safe]` there as a drop-in fix, explicitly deferring the cross-file `protocols_and_impls_from_paths` flow as "out of scope"; the elixir.ex reviewer saw the unsafe manifest decode and atom injection but classified `protocols_and_impls_from_paths`/`parse_manifest` only as DoS/atom sources and never traced those atoms into a `File.rm`/`File.write!`/`:code.delete` sink located in another file — so neither could see that the atoms crossing the boundary are produced in elixir.ex and consumed unconfined in protocol.ex.
- **Suggested fix** — Confine the filename at the protocol.ex sinks regardless of source: in `remove_consolidated/2` and `consolidate_each/4`, use `Path.basename("#{Atom.to_string(protocol)}.beam")` (or skip any protocol atom whose string form contains a path separator or `..`) so consolidation artifacts can only ever land directly under `output`. Do **not** rely on `[:safe]` in protocol.ex's `read_manifest` alone — it does not cover the Path B / umbrella flow, whose atoms come from `Mix.Compilers.Elixir` manifest readers; harden those decodes (`elixir.ex:356`, `:932`, and `protocols_and_impls_from_paths`) as a coordinated set.

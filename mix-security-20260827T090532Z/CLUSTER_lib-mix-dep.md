# Cluster cross-file findings

#### `CSCAN-cluster-lockfile-key-injection-from-dep-name`

- **Finding ID** — `CSCAN-cluster-lockfile-key-injection-from-dep-name`
- **Severity** — High
- **Confidence** — high
- **Files involved**
  - `elixir/lib/mix/lib/mix/dep/loader.ex:145-179` (untrusted `app` atom enters the `Mix.Dep` struct with only `is_atom/1` enforced), `loader.ex:344-366` (`rebar_dep/4`), `loader.ex:338-342` / `loader.ex:372-388` (`to_dep`/`rebar_children` feeding rebar app atoms through)
  - `elixir/lib/mix/lib/mix/dep/fetcher.ex:52-90` (`do_fetch/3`, esp. line 81 `Map.put(lock, app, new)`), `fetcher.ex:98-126` (`do_finalize/3`, esp. line 119 `Map.merge` and line 120 `Mix.Dep.Lock.write(lock, opts)`)
  - `elixir/lib/mix/lib/mix/dep/converger.ex:73-77`, `converger.ex:217-231`, `converger.ex:253-255` (the converge/`put_lock` plumbing that carries the lock map, keyed by the tainted `app`, from `do_fetch` back to `do_finalize`)
  - `elixir/lib/mix/lib/mix/dep/lock.ex:52-57` (`write/2` interpolates the map **key** unescaped) and `lock.ex:25-36` (`read/1` `Code.eval_quoted` — the detonation sink), reached again via `converger.ex:88` `Mix.Dep.Lock.read()`
  - Supporting (outside cluster, read to confirm provenance/return values): `lib/mix/lib/mix/rebar.ex:79` (`:file.consult`), `rebar.ex:133-162` (`parse_dep` passes the consulted atom through verbatim), `lib/mix/lib/mix/scm/git.ex:105-115,296-299` (`checkout` returns a non-nil `{:git, …}` lock)
- **Finding shape** — Taint across files (untrusted data parsed in file A flows into a code-eval sink in file B without re-validation) **and** "safe because the caller checks" broken (lock.ex assumes the key is operator-controlled; the caller in this cluster feeds an attacker-controlled key).
- **Evidence**
  - `lock.ex:54` emits each lock line as `~s(  "#{app}": #{inspect(rev, limit: :infinity)},\n)`. The **value** is passed through `inspect/2` (the lock.ex per-file pass proved this makes hostile `rev` strings round-trip harmlessly), but the **key** `#{app}` is raw `to_string(app)` inserted between two literal `"` — no `inspect`, no escaping. An `app` atom whose name contains `"` breaks out of the quoted key.
  - `lock.ex:28-31` then `read/1` runs the resulting file through `Code.string_to_quoted` **and `Code.eval_quoted`**, executing any expression the broken-out key introduced. This read fires on the next Mix command (e.g. `converger.ex:88`).
  - The key is attacker-controlled and un-sanitized: `loader.ex:149/153/161` only require `is_atom(app)`; `rebar.ex:79` obtains that atom from `:file.consult` of a **transitive** `rebar.config` (data parsing, *not* code execution — established by the fetcher per-file pass), and `rebar.ex:133-162` (`parse_dep`) passes it through unchanged. Neither `loader.ex`, `converger.ex`, nor `fetcher.ex` ever validates the atom's characters. An Erlang quoted atom `'a": System.cmd("touch",["pwned"]), "z'` is legal and survives verbatim.
  - The tainted atom becomes a lock **key**: in `do_fetch` (`fetcher.ex:71-81`) a fresh git-sourced rebar dep hits `out_of_date?` → `scm.checkout(opts)`, which (`git.ex:296-299`) returns `{:git, url, rev, opts}` (non-nil), so `Map.put(lock, app, new)` (`fetcher.ex:81`) stores `app` as a key. `do_finalize` merges it (`fetcher.ex:119`) and calls `Mix.Dep.Lock.write(lock, opts)` (`fetcher.ex:120`), which writes the poisoned `mix.lock`.
  - Net result: a transitive Erlang/rebar dependency that ships *only* a data `rebar.config` (no code runs on the victim during resolution) causes Mix to write a `mix.lock` whose next `read/1` executes attacker code on the developer/CI host — and the poison persists in the committed lockfile and propagates to every collaborator who pulls it.
- **What the per-file pass missed** — `lock.ex`'s reviewer saw the unescaped key but downgraded it to a caveat on the belief that "`app` is the OTP application name sourced from operator-declared `deps` in `mix.exs`," while the `fetcher.ex`/`loader.ex` reviewers proved `app` is attacker-controllable from a transitive `rebar.config` yet only traced it into the *path* sinks (`dest`/`build`/`mark_as_fetched`), never to the lockfile-key write; only joining the two facts across the three files exposes the write-injection→eval RCE.
- **Suggested fix** — In `lock.ex:54`, serialize the key with `inspect/1` exactly as the value already is, e.g. `~s(  #{inspect(app)}: #{inspect(rev, limit: :infinity)},\n)` (or `Kernel.inspect(Atom.to_string(app))` to preserve the string-key style), so a hostile atom name round-trips as an escaped literal instead of live code. Defense-in-depth: validate dependency app atoms against `~r/\A[a-z]\w*\z/` at the loader boundary (`with_scm_and_app`), which also closes the sibling path-traversal findings, and make `read/1` parse the lockfile as literal data rather than `Code.eval_quoted`.

# Security Scan Summary — `elixir/lib/mix` (Mix build tool)

**Scope:** Mix, Elixir's build tool / package manager (commit `3389f84`). Per the threat model, the defended boundary is *untrusted remote/dependency content* (malicious archives, transitive rebar/Hex deps, MITM), **not** the operator — `mix.exs`/`config` run as code by design. The highest-value findings are exactly those where **dependency-supplied *data*** (not code) crosses into a code-eval, arbitrary-write, or arbitrary-delete sink, since those defeat the one boundary Mix claims to hold.

**Method note:** No `VALIDATION.md` present. Ranking uses report-declared severity/confidence; the top findings are `verified` with reproductions. The three `CROSS_FILE.md` "Contradicted" ledger rows were all adjudicated in favor of the owning file (folded into the findings below), and one "Unresolved" row (protocol-atom traversal) was *closed* by a cluster finding. Residual genuinely-unresolved items are listed at the end.

---

## 1. Lockfile key-injection → arbitrary code execution from a transitive rebar dependency  **(High, verified)**
[`CSCAN-cluster-lockfile-key-injection-from-dep-name`](./CLUSTER_lib-mix-dep.md#cscan-cluster-lockfile-key-injection-from-dep-name) (cluster: `dep/loader.ex` + `fetcher.ex` + `converger.ex` + `lock.ex`) — with enabling sink [`CSCAN-lock-lockfile-code-eval`](./lib-mix-dep-lock.ex.md#cscan-lock-lockfile-code-eval) (`dep/lock.ex:31`, Medium)

A transitive Erlang/rebar dependency that ships **only a data `rebar.config`** (no code runs during resolution) can declare a sub-dependency whose *name* is a crafted Erlang atom such as `'a": System.cmd("touch",["pwned"]), "z'`. Mix enforces only `is_atom/1` on dep names, so that atom becomes a **`mix.lock` map key**, which `lock.ex:54` interpolates **unescaped** between quotes (the *value* is `inspect`-escaped; the key is not). On the next Mix command, `Mix.Dep.Lock.read/1` runs the lockfile through **`Code.eval_quoted`**, executing the attacker's expression on the developer/CI host. The poison **persists in the committed lockfile and propagates to every collaborator** who pulls it. No single-file reviewer caught this: `lock.ex` assumed the key was operator-controlled; only joining loader/fetcher/lock across files exposes the write-injection→eval RCE. The underlying "`mix.lock` is `eval`'d at all" primitive is independently a **partial-trust RCE** (a lockfile-only dependency-bump PR or update-bot commit looks like hash noise but detonates on checkout; same for `Mix.install(lockfile: <foreign path>)`). *Fix: serialize the key with `inspect/1`; parse the lockfile as literal data instead of `Code.eval_quoted`; validate dep app atoms against `~r/\A[a-z]\w*\z/` at the loader boundary.*

## 2. Dependency app-name path traversal at `mix deps.get` — arbitrary file delete/plant before any code runs  **(High, verified/reproduced)**
[`CSCAN-loader-dep-app-name-traversal`](./lib-mix-dep-loader.ex.md#cscan-loader-dep-app-name-traversal) (`dep/loader.ex:182`) + [`CSCAN-crossfile-dep-app-name-path-traversal-underdismissed`](./CROSS_FILE.md#cscan-crossfile-dep-app-name-path-traversal-underdismissed)

Same root cause, different sink: `with_scm_and_app/5` builds `dest`/`:checkout` via `Path.join(deps_path, Atom.to_string(app))` with **no `..`/segment confinement**. A transitive rebar dep declaring a sub-dep named `'../../PWNED_SENTINEL'` yields `deps/../../PWNED_SENTINEL`, which `Mix.SCM.Git.checkout/1` feeds to **`File.rm_rf!` + `git init`** — **at fetch time, before any compilation**. Reproduced end-to-end: files *outside the project tree* were deleted by a plain `mix deps.get`. The cross-file report flags that **two neighbor files wrongly "ruled out" this exact sink** (`scm/git.ex` called the checkout path "Mix-internal, safe"; `deps.compile.ex` argued it "adds no capability beyond by-design RCE") — both dismissals are locally unsound; `loader.ex` owns the authoritative finding. Impact: arbitrary directory/file deletion + attacker-content planting as the build user (e.g. `~/.ssh`, sibling checkouts). *Fix: `Path.safe_relative`/single-segment check where the path component is built.*

## 3. `mix archive.install` zip-slip — the folder's primary safety invariant is bypassable  **(High, verified end-to-end)**
[`CSCAN-archive.install-zipslip-lh-cd-differential`](./lib-mix-tasks-archive.install.ex.md#cscan-archiveinstall-zipslip-lh-cd-differential) (`tasks/archive.install.ex:137`)

`validate_archive_path!` — the control the THREAT_MODEL names as the **primary safety invariant** of this folder — validates the **central-directory** names from `:zip.list_dir`, but `:zip.extract` writes to the **local-file-header** names, and OTP's `check_dir_level` checks only *net* `..` depth, not the running minimum. A crafted `.ez` whose CD name is benign (`evilpkg/pwned.txt`) but whose LH name is `x/../../../../y1/y2/y3/PWNED.txt` **writes outside the extraction dir, up to filesystem root**, escalating trivially to code execution (drop a `.beam` into `~/.mix/` or another auto-loaded archive's `ebin/`). Reproduced against the real `mix archive.install` (wrote `/tmp/y1/y2/y3/PWNED.txt`). Requires the operator to install an attacker-supplied `.ez` — a cautioned action, but `validate_archive_path!` exists *specifically* to make a malicious archive safe, so defeating it is in-scope. Two related Lows in the same file: a **dead symlink type-guard** (can never fire; safe only because bundled OTP `:zip` happens not to create symlinks) and **ANSI injection** via the raw-printed archive root name. *Fix: extract per-entry to Mix-canonicalized, confinement-checked paths; don't trust `list_dir` names as a proxy for extract writes.*

## 4. Unauthenticated loopback pub/sub deserialization → aborts any BEAM running Mix  **(High per owning file / Medium cross-file consensus, verified)**
[`CSCAN-pubsub-unsafe-binary-to-term`](./lib-mix-sync-pubsub.ex.md#cscan-pubsub-unsafe-binary-to-term) (`sync/pubsub.ex:266`) — corroborated by [`CSCAN-utils-binary-to-term-atom-exhaustion`](./lib-mix-utils.ex.md#cscan-utils-binary-to-term-atom-exhaustion), [`CSCAN-cluster-pubsub-unsafe-binary-to-term`](./CLUSTER_lib-mix-2.md#cscan-cluster-pubsub-unsafe-binary-to-term), [`CSCAN-cluster-pubsub-loopback-untrusted-deserialization`](./CLUSTER_lib-mix-sync.md#cscan-cluster-pubsub-loopback-untrusted-deserialization)

`Mix.Sync.PubSub`'s subscriber decodes bytes off an **unauthenticated loopback TCP socket** with `non_executable_binary_to_term/1` — which defaults to **no `:safe`** — and decodes **before** any hash/subscription check. Any local process reaching the (world-discoverable `port_<N>` file or port-scanned) port can intern unbounded atoms → **atom-table exhaustion → unrecoverable VM abort** of any `mix test`/LSP/dev-server. Verified: one 5 MB payload interned 200,000 atoms (limit 1,048,576). Same sink yields a **decompression bomb** ([`CSCAN-pubsub-decompression-bomb`](./lib-mix-sync-pubsub.ex.md#cscan-pubsub-decompression-bomb), Medium — ~1000× expansion, `:safe` does not bound it) and a **slowloris body-recv hang** that freezes all subscriptions ([`CSCAN-pubsub-infinite-body-recv`](./lib-mix-sync-pubsub.ex.md#cscan-pubsub-infinite-body-recv), Medium). The cluster reports add an **integrity angle**: `task.compiler.ex` publishes real `{:modules_compiled,…}` events consumed by dependency listener modules, so the unauthenticated transport makes those **compile events forgeable**. *Note: owning file rates atom-exhaustion High; utils/cluster rate the primitive Medium (local, DoS-only). Fix: pass `[:safe]`, cap `size` before `recv`, spawn per-connection, gate on a per-subscriber secret.*

## 5. Protocol-consolidation & module-path traversal via poisoned `_build` manifest  **(Medium, verified)**
[`CSCAN-cluster-consolidation-traversal-via-elixir-manifest`](./CLUSTER_lib-mix-compilers.md#cscan-cluster-consolidation-traversal-via-elixir-manifest) (cluster: `compilers/elixir.ex` + `compilers/protocol.ex`); per-file [`CSCAN-elixir-manifest-module-path-traversal`](./lib-mix-compilers-elixir.ex.md#cscan-elixir-manifest-module-path-traversal), [`CSCAN-elixir-manifest-unsafe-binary-to-term`](./lib-mix-compilers-elixir.ex.md#cscan-elixir-manifest-unsafe-binary-to-term)

`Mix.Compilers.Elixir` reads `compile.elixir` manifests/checkpoints with **plain `binary_to_term`** (no `:safe`, and written `:compressed` → ~1030× decompression bomb, verified). Module/protocol **atoms** read from that manifest are used verbatim as filesystem paths: an atom like `:"../../../../tmp/victim"` drives `File.rm` / `File.write!` / `:code.delete` **outside the tree on an ordinary `mix compile`** (reproduced: deleted `/tmp/cscan_cp_victim.beam`). Cross-file: the tainted atoms are *produced* by two readers in `elixir.ex` and *consumed unconfined* in `protocol.ex` — neither file confines them, so the per-file `[:safe]`-in-protocol.ex fix misses the umbrella/path-dep path. Gated on the `_build` trust boundary (committed `_build` in a cloned repo, restored CI cache, or path-dep build dir). This also **closes the one "Unresolved" cross-file ledger row** (protocol-atom traversal). *Fix: `Path.basename` confinement at the protocol.ex sinks + harden the elixir.ex decodes as a set.*

## 6. `mix release` app-vsn path traversal  **(Medium, verified)**
[`CSCAN-release-app-vsn-path-traversal`](./lib-mix-release.ex.md#cscan-release-app-vsn-path-traversal) (`release.ex:836`)

`copy_app/2` interpolates a dependency's `.app` **`vsn`** field — read verbatim via `:file.consult` — into a filesystem path with no validation. A dep whose `{vsn, "0/../../../../PWNED"}` steers `copy_app` **outside `<release>/lib`**: writes app contents to an attacker-named dir on first `mix release`, and `File.rm_rf!` recursively deletes it on re-run (both reproduced). For a **pure-Erlang/rebar or precompiled `.app`, `vsn` is declarative data — no dependency code executes** to obtain the primitive. *Fix: reject path separators/`..` in `vsn` (and `app`) before building the path; same guard at `tasks/release.ex:1175`.*

## 7. `deps.partition` predictable-tempfile hijack + all-interfaces coordination socket  **(Medium ×2, verified primitives)**
[`CSCAN-deps.partition-config-tmpfile-hijack`](./lib-mix-tasks-deps.partition.ex.md#cscan-depspartition-config-tmpfile-hijack), [`CSCAN-deps.partition-coord-socket-atom-dos`](./lib-mix-tasks-deps.partition.ex.md#cscan-depspartition-coord-socket-atom-dos) (`tasks/deps.partition.ex`)

With the documented (non-default) `MIX_OS_DEPS_COMPILE_PARTITION_COUNT>1`: (a) config is written to a **predictable world-shared `/tmp/mix_deps_partition`** that `File.mkdir_p` reuses through a squatted symlink, then read back with **unsafe `binary_to_term`** — a co-tenant can overwrite `code_path`/project config → **code execution as the victim** during the build; (b) the worker coordination listener binds **`0.0.0.0` (all interfaces), unauthenticated** — an off-host attacker (or co-tenant) can crash the build (`MatchError`/`KeyError`/`ArgumentError` on malformed lines) or **exhaust the atom table** via `<dep>:<novel>` lines through `String.to_unsafe_atom`. The all-interfaces bind is a genuine network exposure, not loopback. *Fix: per-invocation `0700` dir with owner/symlink checks; bind loopback + per-run shared secret; `String.to_existing_atom` + total parsing.*

## 8. `Mix.Sync.Lock` symlink-following write on shared hosts  **(Medium, verified)**
[`CSCAN-lock-symlink-write`](./lib-mix-sync-lock.ex.md#cscan-lock-symlink-write) (`sync/lock.ex:421`)

The lock dir `<tmp>/mix_lock_v2_user<uid>/<md5>` is fully predictable (uid is not secret) and `File.mkdir_p!` reuses a pre-existing dir with no ownership/mode check. An attacker who wins the (persistent — stale files are never cleaned) race plants a symlink at `lock_0`; `File.open!([:read,:write,…])` **follows it**, redirecting the victim's lock writes to **corrupt any victim-writable file** or crash the build (reproduced end-to-end). Content is the victim's own pid/port bytes (integrity/availability, not attacker-chosen). Two related Lows: malformed-lock-file crash and a non-total `await_close` `case` crashable by a hostile lock peer. A **cross-file cluster Low** ([`CSCAN-cluster-lock-ospid-terminal-injection`](./CLUSTER_lib-mix-sync.md#cscan-cluster-lock-ospid-terminal-injection)) adds that the decoded `os_pid` reaches a `Mix.shell().error` interpolation in `project.ex` unescaped → terminal-escape injection. *Fix: `0700` dir + `lstat`/owner check + `O_NOFOLLOW`-equivalent open.*

## 9. `mix format --check-formatted` quadratic-diff DoS  **(Medium, verified)**
[`CSCAN-format-check-formatted-myers-quadratic`](./lib-mix-tasks-format.ex.md#cscan-format-check-formatted-myers-quadratic) (`tasks/format.ex:904/1049`)

The flag is documented for **CI/pre-commit over untrusted contributions**, yet its diff renderer runs an **uncapped O(N²) Myers diff**. A line-disjoint sub-1 MB file consumes tens of seconds of CPU + GB of RAM (verified 23.6 s at N=8000) instead of being cleanly rejected — a **content-only** vector that applies even when `mix.exs`/`.formatter.exs` are trusted. Related Low ([`CSCAN-format-manifest-binary-to-term-unsafe`](./lib-mix-tasks-format.ex.md#cscan-format-manifest-binary-to-term-unsafe)): the same unsafe-`_build`-manifest pattern. *Fix: cap line count/byte size before invoking Myers.*

## Low-severity tier (grouped — mostly self-limited or gated behind an already-trusted boundary)

- **Systemic terminal/ANSI-escape injection via `Mix.Shell`** *(the folder-level pattern from `CROSS_FILE.md`)* — dependency-controlled strings reach the terminal un-sanitized across `dep.ex` `format_status` ([`CSCAN-dep-noappfile-escape-injection`](./lib-mix-dep.ex.md#cscan-dep-noappfile-escape-injection), verified), `utils.ex` tree/JSON/DOT printers ([`CSCAN-utils-tree-printer-terminal-escape`](./lib-mix-utils.ex.md#cscan-utils-tree-printer-terminal-escape--upgraded-from-hedged-assumption-in-first-pass)), `escript.ex` filename, `help.ex` third-party `@moduledoc` rendering, and `archive.install` root name. The `CROSS_FILE.md` "Contradicted" rows (deps.ex/deps.tree.ex claiming these are escaped) were resolved *against* those files. **Root cause: Mix has no central control-byte sanitizer on its shell-output path** — a single sanitizer at the `Mix.Shell` boundary would close all instances. Each is Low because the content that reaches these printers has typically already run as code.
- **Widespread unsafe `binary_to_term` on `_build` manifests** — `app_loader` cache, `dep/elixir_scm.ex`, `compilers/test.ex`, `compilers/protocol.ex`, `format.ex`, and `test.coverage.ex` coverdata (via OTP `:cover.import`). Atom-exhaustion/DoS/decompression, all gated on `_build`/coverdata being attacker-influenced (poisoned CI cache, committed `_build`). Consistent project-wide convention; re-weight upward if untrusted `_build` restore is in your threat model.
- **Atom-table exhaustion via `to_unsafe_atom`/`Module.concat`** from dependency filenames or CLI/task names — `compilers/erlang.ex`, `task.ex` (×2), `do.ex`, `app.tree.ex`, `compile.ex`, `compilers/elixir.ex` purge-path. Mostly operator/CLI-driven (out of scope) or single-shot.
- **`Mix.SCM.Git` defense defects** — [`CSCAN-git-hookspath-literal-quotes`](./lib-mix-scm-git.ex.md#cscan-git-hookspath-literal-quotes) (the `core.hooksPath=''` hook-disable is a literal-quotes no-op pointing hooks at a dir named `''`) and [`CSCAN-git-lock-rev-arg-injection`](./lib-mix-scm-git.ex.md#cscan-git-lock-rev-arg-injection) (lock rev bypasses the `-`-prefix guard → `--upload-pack=<cmd>` git arg-injection). Both Low: gated behind the lockfile-eval, which is easier RCE (see #1).
- **Robustness crashes (uncaught → build abort)** — `local.ex` CSV metadata parse crash on malformed Hex/rebar metadata, `loader.ex` app-vsn iodata crash, `escript.ex` stat-crash, `pubsub` broadcast port-parse crash, `sync/lock.ex` malformed-file/await-close crashes, `task.ex` latin1 crash.
- **`rebar.ex` requirement-regex ReDoS** and **`archive.build` symlink content-capture** — Low.

## Cross-file ledger: unresolved residual risk

The `CROSS_FILE.md` "Contradicted" rows all resolved into findings #1–#2 and the escape-injection pattern above. Genuinely **unresolved / partially-audited** items worth follow-up (nobody confirmed them either way):

- **`local.hex.ex → read_httpc` CSV-byte → request-target validation** — Unresolved; potential request-splitting/SSRF angle in the fetch path that no report closed.
- **`escript.build` `Path.wildcard "**"` symlink traversal** (priv exfil) — asserted, not empirically confirmed.
- **Loader traversal (#2) on Path/Hex SCMs** — only the Git SCM was exercised; Path/Hex `accepts_options` normalization not audited (Hex validates names upstream, so lower risk).
- **`escript.build` `strip_beam`/`:escript.extract` on malformed `.beam`** — explicitly not assessed.

**Bottom line:** the dominant, verified risk class is **transitive rebar/Hex dependency *data* reaching an eval or unconfined-path sink** (#1, #2, #5, #6) — these need no dependency code to execute and defeat exactly the boundary Mix claims to defend; #3 defeats the folder's stated primary invariant. Fixing #1 and #2 is highest priority (both trace to the same missing `~r/\A[a-z]\w*\z/` app-name validation at the loader boundary, plus removing `Code.eval_quoted` from lockfile reads).

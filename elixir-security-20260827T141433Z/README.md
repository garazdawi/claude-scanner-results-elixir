# Security Scan Summary — Elixir (`lib/elixir`, compiler `src/`, stdlib, scripts)

**Scope & evidence basis.** This synthesizes the current reports in `elixir-security-20260827T141433Z`. There is **no security `VALIDATION.md`** (only `COMPLIANCE_VALIDATION.md`, which confirms one RFC finding `real`), so per-finding confidence below is taken from each report's own `verified` (executed/reproduced) vs `asserted` status, plus the `CROSS_FILE.md` Depends-on ledger. Cross-file/cluster findings are featured prominently, and the ledger's **Contradicted/Unresolved** rows are called out where relevant.

**Threat model in one line.** "Untrusted input" here means: (a) **source text** compiled/parsed/formatted (a hostile dependency, an LSP-opened file, a playground/CI check), (b) **untrusted `.beam` artifacts**, and (c) **untrusted data** handed to stdlib APIs at runtime. Compilation-runs-code is a documented boundary, so many compile-time DoS/atom findings are "amplifiers behind a boundary that already executes code" — **except** for *parse-only / format-only tooling* (formatters, linters, language servers, `mix format --check` in CI), which is supposed to never execute the code it processes. That distinction sets the real severity for most of the DoS family.

## 1. Compile-time RCE via `Record.extract/2` on an untrusted Erlang header — **High, verified (PoC)**
`CSCAN-extractor-record-default-eval-rce` (`lib/record/extractor.ex:118`). `Record.extract`/`extract_all` copy each record field's **default-value expression** verbatim from the parsed `.hrl` and run it through `:erl_eval.expr` with **no handler and no restriction**, so any function call in a default (`os:cmd/1`, `file:*`, …) executes with full VM privileges. Reproduced: a `-record(evil, {pwned = os:cmd(...)})` header executed a shell command during `Record.extract`. The realistic boundary is **supply chain**: `Record.extract(from_lib: "some_dep/include/x.hrl")` (or anything it pulls via `-include_lib`) runs that dependency's code on **your build machine**, even though a header looks like a pure declaration. Dominant use (trusted OTP headers, literal paths) is safe; the fix must allow-list constant/guard-safe defaults.

## 2. Unsafe handling of untrusted `.beam` files — deserialization bombs **and** code execution — **Medium (one variant code-exec), verified; CONTRADICTED ledger entry**
A repo-wide pattern: chunks of attacker-controlled `.beam`/`.chunk` files are decoded with non-`:safe`, unbounded `:erlang.binary_to_term/1`, and file-derived atoms/modules drive dynamic dispatch. `CROSS_FILE.md` marks the `elixir_erl → beam_lib/Code "safe decode"` dependency **Contradicted**.
- **Flagship (verified):** `CSCAN-code-fetch-docs-unsafe-binary-to-term` (`code.ex:2383`) — the public `Code.fetch_docs/1` on an arbitrary `.beam` decodes the `Docs` chunk unsafely: a **281 KB crafted beam expanded to 200 MB** (compression bomb → OOM) and **one call minted 100,000 permanent atoms** (→ atom-table exhaustion). Realistic victim: a docs-hosting/indexing service or language server reading uploaded/dependency artifacts. `[:safe]` alone is insufficient (breaks legit unloaded-module docs and doesn't bound allocation).
- **Reaches code execution (cluster, high conf):** `CSCAN-cluster-debug-info-compile-opts-parse-transform` (`elixir_erl.erl:25-42` → `elixir_erl_compiler.erl:71-79`) — a `.beam`'s deserialized `debug_info` `compile_opts` flow **unfiltered** into `compile:noenv_forms`; a leading `{parse_transform, Mod}` makes the compiler run `Mod:parse_transform/2` on attacker forms **during a debug-info fetch** (analyzers/coverage/decompilers that read debug info *without* executing the beam). Fix: strip code-executing options before use.
- **Same family (verified/asserted):** `CSCAN-typespec-untrusted-beam-debug-info` (Medium, `code/typespec.ex` — atom exhaustion + backend-dispatch gadget; code-exec *not* reachable, format pinned `:erlang_v1`), `CSCAN-parallel_checker-beam-chunk-crash-dos` (Medium — crafted beam crashes/hangs the **compiler** via a linked worker), `CSCAN-protocol-consolidate-unsafe-binary-to-term` (Low), `CSCAN-diff-unsafe-binary-to-term` + `CSCAN-diff-beam-chunk-decode-bomb` (Medium, dev/CI `scripts/diff.exs`, verified 1028× bomb + 40k atoms), `CSCAN-infer-binary-to-term-unsafe` (Low, defense-in-depth), `CSCAN-elixir_erl-embedded-term-binary-to-term` (None/safe-by-construction, filed only per always-flag rule).

## 3. Quadratic tokenizer blow-up in the non-NFC diagnostic path — **High, verified**
`CSCAN-tokenizer-nfc-prefix-quadratic` (`unicode/tokenizer.ex:542-550`). A single crafted **non-NFC, mixed-script identifier** drives `invalid_original_prefix/3` to re-NFC-normalize the whole growing prefix per character → Θ(n²), and the identifier length is bounded only by file size. Measured: a **48 KB source with one identifier parsed in 17.8 s vs 42.6 ms** for a benign one (~420×); a few-hundred-KB identifier reaches minutes. Reachable through `Code.string_to_quoted` and therefore **`mix compile`/`mix deps.compile` of a hostile dependency (build machine), `mix format`, ElixirLS, Credo, or any snippet-parsing service** — the 255-codepoint atom cap runs *after* the quadratic work, so it does not bound this.

## 4. Unbounded allocation in the type checker's tuple operations — **High, verified**
`CSCAN-descr-tuple-index-alloc-dos` (`module/types/descr.ex:5634-5642`) with its shared-root companion `CSCAN-apply-unbounded-tuple-type-alloc` (`module/types/apply.ex`, Medium). A single source line such as `Tuple.delete_at(t, 8_000_000)` / `elem(x, 20_000_000)` makes the compiler build `List.duplicate(term(), index)` with an unbounded, source-controlled index → linear-in-N allocation/CPU with no cap (index 8M → 2.66 s; 20M → ~3 GB, verified end-to-end through `Code.compile_string`). Reachable via `mix compile` of untrusted source or an LSP type-checking an opened file. Companion `CSCAN-descr-nested-tuple-quadratic-dos` (Medium) — deeply nested tuple *type* literals are O(depth²) because each BDD leaf re-hashes its full subtree, and the parser imposes no nesting cap.

## 5. Compiler-module pool leaks atoms on the crash path → atom-table exhaustion — **Medium (cluster), high; Unresolved ledger row**
`CSCAN-cluster-compiler-module-pool-atom-leak` (`elixir_compiler.erl` ↔ `elixir_code_server.erl`). The code server bounds atom growth only if every retrieved `elixir_compiler_N` module is returned, but retrieval happens inside the spawned child while the return happens only in `dispatch/4`'s `after` — reached *after* `elixir_erl_compiler:spawn` succeeds. A crash between retrieve and load (e.g. the back-end rejecting successfully-expanded forms, a path the code explicitly anticipates) leaks the slot; sustained post-retrieve crashes drive `Unused` empty and mint a **new permanent atom per compile**, growing the global atom table until the BEAM aborts. Entry point: `Code.compile_string`/`eval_string` of a hostile top-level expression. This is the ledger's one notable **Unresolved** dependency (`code_server → compiler` crash-safe return), now substantiated as a cluster finding.

## 6. `--warnings-as-errors` silently dropped → strict-mode gate is a no-op — **Medium (cluster), high, verified**
`CSCAN-cluster-warnings-as-errors-flag-dropped` (`kernel/cli.ex` → `kernel/parallel_compiler.ex`). `cli.ex` parses and forwards `warnings_as_errors: true`, but `Kernel.ParallelCompiler`'s inner `spawn_workers/5` copies only a fixed option set that **omits `:warnings_as_errors`**, and `verify_modules/4` returns `:ok` regardless of warning count. Net effect: **`elixirc --warnings-as-errors` exits 0 even when files emit warnings** — a CI/build safety gate that appears enforced but is silently bypassed.

## 7. Atom-table exhaustion via `Module.concat` / alias / dispatch atomization — **Medium (cross-file), CONTRADICTED ledger entries**
Two cross-file findings where a relied-upon "bounded atom growth" contract is contradicted by a verified sink:
- `CSCAN-crossfile-aliases-concat-atom-exhaustion` — `elixir_expand`/`elixir_aliases` assume `concat/1` is bounded, but `CSCAN-module-concat-atom-exhaustion` (verified, `module.ex`/`elixir_aliases.erl:175`) confirms `Module.concat` calls `binary_to_atom` (permanent, unbounded); `safe_concat` is the only bounded variant. Any caller forwarding untrusted binaries to `concat` can exhaust the ~1M atom table.
- `CSCAN-crossfile-dispatch-atom-exhaustion` (medium conf) — `elixir_fn`/`elixir_rewrite` rely on `elixir_dispatch` not atomizing untrusted text, but that dismissal was **downgraded to asserted** and its reachability is "Not examined," while its one verified axis shows `list_to_atom` grows the table on novel inputs. Needs direct source verification of whether attacker identifiers reach the sink unbounded.

## 8. Algorithmic-complexity (quadratic/cubic) DoS against compile-, parse-, and format-time tooling — **Medium/High, mostly verified**
A broad, consistent theme: crafted-but-small inputs cost minutes of CPU or gigabytes of memory. Most dangerous against **parse-/format-only tooling** (formatters, linters, LSPs, CI, playgrounds) that is not supposed to execute code. Representative verified findings:
- **Parser:** `CSCAN-elixir_parser-alias-chain-quadratic` (`A.A.…A` via `++`; 256 KB → ~24 s, 1 MB → ~6 min) — hits every `Code.string_to_quoted` consumer.
- **Capture/anon-fn:** `CSCAN-elixir_fn-capture-orddict-quadratic` (`&(&1+…+&N)`; ~25 KB → ~32 s) — services that compile/eval user Elixir.
- **Formatter (`mix format`/LSP/CI):** `CSCAN-formatter-comment-hash-run-quadratic` (a run of `#`; 160 KB → 3.8 s) and `CSCAN-formatter-format-to-string-quadratic` (nested bitstrings/captures).
- **Pretty-printer (runtime):** `CSCAN-algebra-fits-quadratic-dos` (`Inspect.Algebra.fits?/4`; `inspect(untrusted, pretty: true, limit: :infinity)` → 625 KB nested term = 55 s) — logger/debug paths.
- **AST printing / editor tooling:** `CSCAN-normalizer-keyword-quadratic` (`Macro.to_string`), `CSCAN-fragment-nested-alias-quadratic` (autocomplete/hover on a hostile file; 256 KB → ~1 min).
- **Type inference:** `CSCAN-of-cartesian-map-exponential` (union-typed map keys → Cartesian product).
- **Docstring rendering (`h`/`mix help` on a dependency):** `CSCAN-docs-table-cell-quadratic` (53 KB table → 95 MB, can OOM the node), `CSCAN-docs-link-regex-redos` (500 KB → ~85 s), `CSCAN-docs-inline-comment-matcherror` (unterminated `<!--` crashes non-IEx renderers).
- **Stdlib runtime DoS:** `CSCAN-string-invalid-utf8-quadratic` (`String.normalize`; 400 KB → ~10 s), `CSCAN-integer-popcount-quadratic-dos` (O(bits²); 800 kbit → 15.7 s), `CSCAN-float-parse-unbounded-bigint` / `CSCAN-uri-port-to-integer-dos` / `CSCAN-iso-parse-duration-unbounded-integer` (unbounded `binary_to_integer` → `SystemLimitError` on ~1.3 M-digit input), `CSCAN-calendar-strftime-preferred-amplification` (cubic; ~400 B → 8 MB — **treat as High if per-user formats are attacker-controlled**), `CSCAN-version-requirement-bang-warn-amplification` (per-byte `IO.warn` stacktrace flood), `CSCAN-list-myers-difference-quadratic` (16 k elems → 4.3 GB + 29 s), `CSCAN-path-join-quadratic`.
- **Lower-severity cross-file variants (ledger Contradicted):** `CSCAN-crossfile-expand-superlinear-compile-cost` and `CSCAN-crossfile-inspect-algebra-compile-dos` (both behind the compile boundary → Low).

## 9. Runtime crashes on untrusted input (availability) — **Medium/Low, verified**
Un-guarded conversions that raise where the API contract promises graceful handling:
- `CSCAN-string-grapheme-gc-crash` (Medium) — a 3-byte input makes `:unicode_util.gc/1` raise, crashing `length`/`graphemes`/`slice`/… (root cause upstream OTP 29).
- `CSCAN-inspect-charlist-conversion-crash` (Medium) — `Inspect.List` checks only the first 4096 elements then converts the whole list; a bad element past 4096 crashes the inspect safety net used by logging/crash reporting.
- Low crash family: `CSCAN-regex-replace-malformed-backref-crash` & `-offset-forwarded-argerror` & `-untrusted-pattern-redos`; `CSCAN-option_parser-numeric-parse-crash` & `-regex-untrusted-compile`; `CSCAN-string_io-getuntil-unicode-crash` & `-open3-close-noproc`; `CSCAN-uri-new-uri-string-port-dos`; `CSCAN-calendar-strftime-f-precision-crash`; `CSCAN-version-requirement-lexer-utf8-crash`; `CSCAN-string-normalize-raises-invalid`; `CSCAN-json-encode-nonutf8-raw-erlangerror`; `CSCAN-elixir_bitstring-unit-arg-badarith` & `-unpack-specs-if-clause`; `CSCAN-registry-lock-call-timeout` (5 s `GenServer.call` on an unbounded lock hold); `CSCAN-elixir_parser-uncaught-reduce-exception` (asserted).

## 10. Other atom-table exhaustion (Low)
`CSCAN-macro-generate-arguments-atom-exhaustion` (build-time `amount` → `mix compile` crash), `CSCAN-extractor-from-lib-atom-exhaustion`, `CSCAN-descr-alias-segment-atom-creation`, `CSCAN-normalizer-alias-atom-creation`, `CSCAN-fragment-container-atom-exhaustion` (LSP has no atom-safe parse path — options silently stripped), `CSCAN-module-signature-unsafe-atom`, `CSCAN-hash_dict-phash2-hashflood` (unseeded `phash2`, shared with `Map`), plus the cluster `CSCAN-cluster-atom-escape-length-dos` (escape amplification → 255-cap `binary_to_atom` crash in `Macro.to_string`).

## 11. Terminal / log escape injection (Low, verified)
Untrusted bytes reaching a developer terminal, CI log, or LSP diagnostic without sanitization: `CSCAN-elixir_errors-diagnostic-terminal-escape-injection` (raw source snippet incl. ANSI/C0 to stderr — bypasses the tokenizer via disk re-read; hits parse-only tooling), `CSCAN-behaviour-diagnostic-escape-injection` (raw callback-name atom from a dependency), `CSCAN-docs-terminal-escape-passthrough` (dependency docstring escapes on `h`/`mix help`, even with color disabled), `CSCAN-duration-iso8601-error-message-injection`, `CSCAN-identifier-pcm-escape-gap` (Prepended-Concatenation-Marks omitted from the escape set → invisible-char injection / round-trip breakage in `inspect`).

## 12. Data-controlled dispatch gadgets (Low)
Deserialized/attacker-shaped maps drive dynamic module dispatch with no behaviour/allow-list gate: `CSCAN-set-struct-module-dispatch` (`Set.*` over `binary_to_term`'d structs — type-confusion call gadget; no obvious stdlib weaponization, deprecated module), `CSCAN-elixir_quote-macro-escape-struct-dispatch` (`Macro.escape` force-loads a caller-named module's `__escape__/1`), `CSCAN-calendar-strftime-calendar-dispatch-gadget`. Companion `CSCAN-set-dispatch-gadget-absence` (asserted) notes the Low rating holds only if no loaded module exports a matching side-effecting gadget.

## 13. Miscellaneous hardening (Low)
`CSCAN-port-spawn-shell-injection` (docs mis-scope `{:spawn, cmd}` injection to Windows only — on Unix it is *always* `/bin/sh -c "exec <cmd>"`; doc-completeness fix), `CSCAN-system-cmd-arg-null-truncation` (NUL not rejected in `cmd/3` args/`:cd`, defeating a caller's full-string validation), `CSCAN-path-safe-relative-nul-byte`, `CSCAN-io-warn-line-traversal-dos` & `-warn-snippet-file-read` (caller-forwarded `file:`/`line:` → self-amplifying read / one-line file disclosure), `CSCAN-base-noncanonical-decode` (non-injective base64/base32 → malleability if the *encoded* form is trusted for a MAC/dedup/allow-list decision), `CSCAN-json-colliding-keys-duplicate-object` (parser-differential from key stringification collisions), `CSCAN-mix_docs-cdn-script-no-sri` & `CSCAN-elixir_docs-cdn-script-no-sri` (mermaid CDN `<script>` without SRI in generated docs).

## 14. Deprecated-module correctness with availability impact (Low–Medium)
`CSCAN-hash_set-protocol-dispatch-wrong-atom` (Medium) — protocol impls build `:HashSet` instead of `:"Elixir.HashSet"`, so **every** `Enum`/`for`/`inspect` on a `HashSet` raises `UndefinedFunctionError` (deterministic, not attacker-parameterized; `HashDict` shares the defect, filed there as correctness-only). Cluster `CSCAN-cluster-inspect-list-return-contract-mismatch` (Low) — `HashDict`/`HashSet` `inspect` feed a now-`{doc, opts}` return into `concat/1` → trapped `FunctionClauseError` on populated structures. Cluster `CSCAN-cluster-string-replace-forwards-regex-template-crash` (Low) — `String.replace/4` forwards a malformed `\g{}` template into the same `Regex` parser crash. Cluster `CSCAN-cluster-stat-size-undefined-arith` (Low, low conf) — `File.Stat` `size: :undefined` → arithmetic crash in `File.Stream` counting (not shown reachable on Linux).

## 15. RFC compliance note — **Low, validated `real` (stricter than spec, no attacker uplift)**
`CSCAN-elixir-rfc-directional_formatting_not_prohibited` (the only finding covered by `COMPLIANCE_VALIDATION.md`). Elixir **hard-rejects** the nine directional-formatting characters in string literals and comments, whereas UTS #55 §5.1.6 SHOULD-NOT recommends warning-when-effect-spans-a-token rather than outright prohibition. Validated `real` (the recommended scoped-warning path is absent, and comments have no escape hatch), but it is a **deliberate, safer Trojan-Source defense** — no attacker uplift; the only cost is that legitimate raw RTL controls can't appear in source. The rest of the 21-clause Unicode/UAX-31/UTS-39 matrix (NFC enforcement, mixed-script rejection, confusable lint, bidi recognition) is **satisfied** — this codebase's identifier-spoofing posture is strong.

### Cross-file ledger callouts (as requested)
- **Contradicted** dependencies (each became a finding above): `elixir_erl → beam_lib/Code` safe-decode (#2), `elixir_erl → Inspect.Algebra` cost (#8), `elixir_fn/rewrite → dispatch` atomization (#7), `elixir_fn → expand` super-linear (#8), `elixir_expand → aliases` atom-bound (#7), `elixir_expand → dispatch` (#7).
- **Unresolved** (notable): `elixir_code_server → elixir_compiler` crash-safe module return — substantiated as the atom-leak cluster finding (#5); resolving it requires reading `elixir_compiler.erl`'s `retrieve/return` wrapping. Other Unresolved rows (bootstrap build-system invariant, `elixir_clauses` fixpoint semantics, OTP back-end diagnostics, IEx distribution cookie) are out-of-folder trust assumptions, not defects.

### Highest-value remediations
1. Bound/allow-list the shared **`binary_to_term`-on-`.beam`** path (spawn a `max_heap_size` decoder, cap chunk size, reject `parse_transform`/executable `compile_opts`) — closes #2 and most of the beam family at once.
2. Gate `Record.extract` default evaluation to constant/guard-safe expressions (#1).
3. Make the three **High** compile/parse-time hot spots linear/bounded: tokenizer NFC diagnostic (#3), descr/apply tuple-index allocation (#4), and add a nesting/identifier-length cap consulted by parse-only tooling.
4. Fix the two **compiler-integrity** defects: crash-safe compiler-module return (#5) and honoring `--warnings-as-errors` (#6).

## Consolidated clauses
1. IDENT_XID_SYNTAX — Unquoted identifiers/atoms/calls are restricted to the default identifier syntax (Start = XID_Start, Continue = XID_Continue) via the delegated identifier_tokenizer, rejecting anything outside it. (cites: Unicode UAX #31 §2, R1-1) (quote: "setting Start and Continue to the properties XID_Start and XID_Continue, respectively") [SHALL]
2. IDENT_NFC_FORM — Unquoted identifiers, atoms, variables and calls must be in (and are tested/compared against) canonical composition NFC form, both when producing the atom and when testing/rejecting the source token; non-NFC input is rejected with an NFC/NFKC suggestion. (cites: Unicode UAX #31 §5, R6/R4; Unicode UTS #39 §3.1.1.1; Unicode UTS #55 §3.1.1; Unicode UAX #15 §4) (quote: "Allowed identifiers must be in the specified Normalization Form.") [MUST]
3. IDENT_MIXED_SCRIPT_REJECT — Identifiers mixing scripts in a confusable way are hard-rejected (mixed_script error / diagnosed confusing chunks) via a restriction level requiring characters to stay within the identifier profile / single resolved script, per the spoofing mechanisms UAX #31 defers to UTS #39. (cites: Unicode UAX #31 §5; Unicode UTS #39 §5.2; Unicode UTS #55 §5.1.2.2) (quote: "Where spoofing concerns are relevant, the mechanisms described in Unicode Technical Standard #39 should be used.") [MUST]
4. IDENT_CONFUSABLE_LINT — Confusable identifiers (across a file, or against another relevant identifier or a reserved word) are surfaced as lint warnings (unicode_lint_warnings / confusable_skeleton), implementing the recommended confusability defense. (cites: Unicode UAX #31 §5; Unicode UTS #55 §5.1.1) (quote: "Where spoofing concerns are relevant, the mechanisms described in Unicode Technical Standard #39 should be used.") [SHOULD]
5. IDENT_DEFAULT_IGNORABLE_EXCLUDED — Default_Ignorable_Code_Points (e.g. ZWJ/ZWNJ) are excluded from general-purpose identifiers by the tokenizer profile rather than being silently accepted. (cites: Unicode UAX #31 §2.3) (quote: "A profile should be used to remove them from general-purpose identifiers (along with other Default_Ignorable_Code_Points)") [SHOULD]
6. IDENTIFIER_PROFILE_ALLOWED_ONLY — Identifiers must be restricted to Allowed characters; codepoints with Identifier_Status=Restricted are rejected during tokenization. (cites: Unicode UTS #39 §3.1) (quote: "does not permit any characters in \p{Identifier_Status=Restricted}, unless it documents the additional characters") [SHALL]
7. ALIAS_ASCII_ONLY — Module aliases must satisfy the ASCII-Only restriction level, permitting only ASCII characters without punctuation. (cites: Unicode UTS #39 §5.2) (quote: "characters in the string must also be in the identifier profile") [MUST]
8. PATTERN_WHITE_SPACE_NEWLINES — Treat the Pattern_White_Space set (incl. Unicode line/para separators) as the definitive end-of-line/horizontal-space characters. (cites: Unicode UTS #55 §3.2) (quote: "which specifies the characters to be interpreted as end of line and horizontal space") [RECOMMENDED]
9. NO_IGNORE_DEFAULT_IGNORABLES — Do not strip/ignore Default_Ignorable_Code_Point characters when comparing identifiers (case-sensitive). (cites: Unicode UTS #55 §3.1.1) (quote: "They should not ignore default ignorable code points in identifier comparison") [SHOULD NOT]
10. FORMAT_CONTROLS_BETWEEN_ATOMS — Allow ignorable format controls between atoms/lexical elements to the extent possible. (cites: Unicode UTS #55 §3.2) (quote: "languages allow the ignorable format controls between atoms, as defined in Section 4.1, to the extent possible") [RECOMMENDED]
11. PATTERN_SYNTAX_RESERVATION — Reserve Pattern_Syntax character classes for future syntax/identifier assignment. (cites: Unicode UTS #55 §3.2) (quote: "meet requirements UAX31-R3b Pattern_Syntax Characters") [RECOMMENDED]
12. OPERATOR_NORMALIZATION_EQUIV — User-definable operators should be treated as equivalent under normalization. (cites: Unicode UTS #55 §3.2) (quote: "operators should be treated as equivalent under normalization") [SHOULD]
13. GENERAL_SECURITY_PROFILE_WARNING — Provide a mechanism to warn about identifiers outside the General Security Profile. (cites: Unicode UTS #55 §5.1.3) (quote: "provide a mechanism to warn about identifiers that are not in the General Security Profile for identifiers") [SHOULD]
14. DIRECTIONAL_FORMATTING_NOT_PROHIBITED — Do not outright prohibit directional formatting characters (they are needed for correct bidi display); prefer warning when their effect spans atoms. (cites: Unicode UTS #55 §5.1.6) (quote: "Implementations should not prohibit the use of the directional formatting characters") [SHOULD NOT]
15. SCRIPT_SINGLE_VALUE — Every code point is assigned exactly one Script property value, so identifier/script logic may treat sc as a total function. (cites: Unicode UAX #24 §2.1) (quote: "every Unicode code point is assigned a single Script property value") [SHALL]
16. SCX_NONEMPTY_SET — Each code point's Script_Extensions is exactly one non-empty set; unassigned, private-use, and noncharacter code points resolve to { Unknown }, never the empty set. (cites: Unicode UAX #24 §3.1) (quote: "The empty set is not allowed; the scx value for unassigned, private use, and non-character code points is the set { Unknown }") [MUST]
17. SCX_CONTAINS_EXPLICIT_SC — When a code point's Script value is explicit, that value must also be an element of its Script_Extensions set. (cites: Unicode UAX #24 §3.1) (quote: "then that value must be an element of the scx set for that code point as well") [MUST]
18. COMBINING_MARK_NO_SCRIPT_BREAK — Implementations determining script boundaries must not break between a combining mark and its base character. (cites: Unicode UAX #24 §5.2) (quote: "should never break between a combining mark...and its base character") [SHOULD NOT]
19. COMBINING_SEQUENCE_INHERIT_FIRST — A combining character sequence is treated as having the Script property value of its first character when resolving script runs. (cites: Unicode UAX #24 §5.2) (quote: "as having the Script property value of the first character in the sequence") [RECOMMENDED]
20. NORMALIZATION_TRANSFORM_CONFORMANT — the normalization transforms the tokenizer relies on (NFC for identifier canonicalization, `characters_to_nfkc_list` for the compatibility-form suggestion) must be conformant transforms reproducing NormalizationTest.txt results. (cites: Unicode UAX #15 §4) (quote: "must be able to produce the results of the conformance test specified in the NormalizationTest.txt data file") [MUST]
21. BIDI_FORMATTING_CHARS_REORDER_DISPLAY — The explicit directional formatting characters (embeddings LRE/RLE U+202A/B, overrides LRO/RLO U+202D/E, isolates LRI/RLI/FSI U+2066/7/8, and their pops PDF U+202C / PDI U+2069) reorder the displayed order of the surrounding characters under the algorithm, so a process handling such source text must recognize and account for them rather than treat their code-point order as their visual order. (cites: Unicode UAX #9 §Conformance/C1) (quote: "shall display all visible representations of characters") [SHALL]

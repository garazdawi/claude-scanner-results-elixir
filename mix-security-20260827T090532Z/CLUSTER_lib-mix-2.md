# Cluster cross-file findings

#### `CSCAN-cluster-pubsub-unsafe-binary-to-term`

* **Finding ID** — `CSCAN-cluster-pubsub-unsafe-binary-to-term`
* **Severity** — Medium
* **Confidence** — high
* **Files involved**
  * `elixir/lib/mix/lib/mix/utils.ex:21-34` (definition of `non_executable_binary_to_term/2` and its documented `:safe` precondition) and `:54-63` (`non_executable_terms` permits atoms/numbers/bitstrings/pids/refs, rejecting only funs)
  * `elixir/lib/mix/lib/mix/task.compiler.ex:346-362` (`notify_modules_compiled/1` — the cluster's publisher into this channel) and `:55-91` (the listener message contract `{:modules_compiled, info}` / `{:dep_compiled, info}` whose integrity the docs assume)
  * pivotal sibling (out-of-cluster) sink: `elixir/lib/mix/lib/mix/sync/pubsub.ex:266` (`Mix.Utils.non_executable_binary_to_term(binary)` called with **no** `[:safe]`), reachable via the unauthenticated loopback transport at `:27-28`, `:103-124`, `:237-262`
* **Finding shape** — Taint across files / "safe because the caller checks" broken (a cluster-defined deserialization primitive whose documented `:safe` precondition is violated by the folder sibling that feeds it untrusted bytes; the primitive's *name* over-promises the safety its *implementation* in `utils.ex` does not provide).
* **Evidence**
  * `utils.ex:21-27` states plainly: *"By default this function does not restrict atoms … If you want to avoid atoms from being created, then you can pass `[:safe]`."* The walker at `utils.ex:54-58` returns any `is_atom(other)` term unchanged — only anonymous functions hit the rejecting catch-all at `:60-63`. So without `[:safe]`, `:erlang.binary_to_term(binary, opts)` at `utils.ex:31` freely interns new atoms and materializes arbitrarily large terms.
  * `sync/pubsub.ex:266` calls `Mix.Utils.non_executable_binary_to_term(binary)` with the default empty opts. The `binary` is read straight off a TCP socket in `receive_message/1` (`recv(socket, size)` at `:248`, where `size::unsigned-integer-64` is fully attacker-supplied at `:246`), and `decode_data/1` runs **before** any hash-routing check (routing happens later in `handle_info/2` at `:161-169`), so the deserialize fires on every accepted connection regardless of key.
  * The channel is unauthenticated: `@listen_opts` binds `127.0.0.1` (`:26-28`), `receive_message/1` accepts any connection and only checks a fixed literal tag `"mixpubsub"` plus a hash that is itself the directory name (`path/1` at `:274-277` → `Base.url_encode64(md5(key))`), which is world-listable because `create_subscription_file/2` (`:220-224`) makes the tree under `System.tmp_dir!()` with default (`0755`) perms. Any local user on a shared build/CI host can therefore enumerate the port + hash and inject a crafted `term_to_binary` payload.
  * `task.compiler.ex:361` publishes real `{:modules_compiled, info}` events onto this exact channel via `Mix.Sync.PubSub.broadcast/2`, and `:55-91` documents that subscribed **listener modules (living in project dependencies)** consume `info` and act on it (e.g. reload modules). Because the transport authenticates nothing, those events are forgeable, so the missing `:safe` is compounded by a message-integrity gap on a contract this cluster file defines and relies on.
* **What the per-file pass missed** — A `pubsub.ex`-only reviewer sees a call named `non_executable_binary_to_term` and reasonably assumes it is already safe; only by reading `utils.ex` does one learn the primitive deliberately does *not* block atom creation or bound term size by default, and only by reading `task.compiler.ex` does one see this loopback channel carries integrity-sensitive compile events to dependency code — no single-file reviewer sees both the weak guarantee and the untrusted, unauthenticated feed at once.
* **Suggested fix** — In `sync/pubsub.ex:266` pass `[:safe]`: `Mix.Utils.non_executable_binary_to_term(binary, [:safe])`, which blocks new-atom creation (closing the atom-table–exhaustion DoS) at no cost to legitimate `{:modules_compiled, info}` traffic (all atoms in those messages already exist in the receiver). Additionally cap the accepted `size` at `pubsub.ex:246` to a small maximum before `recv/2` to bound the memory-amplification (compressed external-term) DoS that `:safe` does not address, and — for the forged-event concern — gate acceptance on a per-subscriber secret rather than the world-readable port/hash alone.

_No other finding in this cluster requires two or more of {`state.ex`, `task.compiler.ex`, `task.ex`, `tasks_server.ex`, `utils.ex`}: the remaining cross-file edges (compiler names → `command_to_module` atom creation, `MIX_ENV`/`MIX_TARGET` → `String.to_unsafe_atom`, the `:public` ETS in `state.ex`/`tasks_server.ex`, task-name → alias-atom lookup) are all driven by operator/CLI/config input, which the folder threat model places out of scope._
